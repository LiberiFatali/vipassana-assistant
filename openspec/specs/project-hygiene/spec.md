# Specification: Project Hygiene

## Purpose
Internal codebase-quality requirements ensuring the repository stays free of committed runtime artifacts, dead code, duplicate agent-construction paths, and stale setup documentation. These are maintainability requirements, not user-facing behavior.

## Requirements
### Requirement: No Generated Runtime Artifacts in Version Control
The repository SHALL NOT track files generated by running the application locally (e.g. ADK session databases), and `.gitignore` SHALL exclude the directories that produce them.

#### Scenario: ADK session database is untracked
- **WHEN** a contributor runs `git ls-files` after running the chatbot locally (which creates `chatbot_agent/.adk/session.db`)
- **THEN** no files under `chatbot_agent/.adk/` appear in the tracked file list

### Requirement: No Unreferenced Dead Code in Shipped Packages
Modules in `chatbot_agent/` and `vipassana_mcp/` SHALL NOT contain functions, constants, or entry-point stubs that have zero callers and are not part of a documented external interface (CLI entry point, MCP tool, or public API re-export).

#### Scenario: Repo-wide search finds no remaining references
- **WHEN** a maintainer greps the repository for `CENTER_ALIASES`, `resolve_center`, or `chatbot_agent/main.py`
- **THEN** no matches are found in tracked source files

### Requirement: Single Agent Construction Path
Importing the `chatbot_agent` package SHALL NOT construct a `google.adk.agents.Agent` instance as a side effect. Only the ADK entry-point module (`chatbot_agent/agent.py`) SHALL call `create_agent()`, so at most one `Agent`/`McpToolset` pair is ever built per process.

#### Scenario: Static-only import does not build an Agent
- **WHEN** `eval_agent.py` imports `sanitize_urls` and `TRUSTED_DOMAINS` from the `chatbot_agent` package
- **THEN** that import does not construct a `google.adk.agents.Agent` or `McpToolset` instance

#### Scenario: ADK entry point still resolves an agent
- **WHEN** ADK tooling imports `chatbot_agent.agent`
- **THEN** `chatbot_agent.agent.root_agent` is a fully configured `Agent` instance, unchanged in behavior from before this change

### Requirement: Setup Documentation Matches Actual Layout
`README.md` SHALL describe the package layout and commands that actually exist in the repository, not a previous or planned one.

#### Scenario: Following README setup steps succeeds
- **WHEN** a new contributor follows the README's install and run instructions exactly as written
- **THEN** every referenced path and command (e.g. `chatbot_agent/cli_chatbot_agent.py`, `python -m chatbot_agent.cli_chatbot_agent`) exists and works in the current repository
