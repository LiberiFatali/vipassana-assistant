# Specification: Project Hygiene

## Purpose
Internal codebase-quality requirements ensuring the repository stays free of committed runtime artifacts, dead code, duplicate agent-construction paths, and stale setup documentation. These are maintainability requirements, not user-facing behavior.
## Requirements
### Requirement: No Generated Runtime Artifacts in Version Control
The repository SHALL NOT track files generated by running the application locally (e.g. Vercel build output, dependency installs, local env files), and `.gitignore` SHALL exclude the directories that produce them.

#### Scenario: ADK session database is untracked
- **WHEN** a contributor runs `git ls-files` after the legacy Python codebase is removed
- **THEN** no files under a `chatbot_agent/` directory (including any `.adk/session.db`) appear in the tracked file list

#### Scenario: Local dev artifacts are untracked
- **WHEN** a contributor runs `vercel dev` or `npm install` locally (which creates `.vercel/`, `node_modules/`, and `.env`)
- **THEN** no files under `.vercel/` or `node_modules/` appear in the tracked file list, and local env files are ignored

### Requirement: No Unreferenced Dead Code in Shipped Packages
Modules under `api/` SHALL NOT contain functions, constants, or entry-point stubs that have zero callers and are not part of a documented external interface (HTTP route, AI SDK tool, or exported helper used by tests).

#### Scenario: Repo-wide search finds no remaining references
- **WHEN** a maintainer greps the repository for `chatbot_agent`, `vipassana_mcp`, or `CENTER_ALIASES`
- **THEN** no matches are found in tracked source files

### Requirement: Single Agent Construction Path
Importing the agent modules SHALL NOT construct an LLM agent or open a provider connection as a side effect. Only the request handler in `api/chat.js` SHALL build the agent, so at most one agent instance is constructed per request.

#### Scenario: Static-only import does not build an Agent
- **WHEN** a test imports `sanitize_urls` and `TRUSTED_DOMAINS` from `api/sanitize.js` or the system prompt from `api/system-prompt.js`
- **THEN** that import does not construct an agent, call the LLM provider, or perform network I/O

#### Scenario: ADK entry point still resolves an agent
- **WHEN** a client POSTs to `/api/chat`
- **THEN** the handler constructs a fully configured agent (system prompt + knowledge base + tools) and returns a sanitized response, unchanged in behavior from the pre-refactor agent

### Requirement: Setup Documentation Matches Actual Layout
`README.md` SHALL describe the package layout and commands that actually exist in the repository, not a previous or planned one.

#### Scenario: Following README setup steps succeeds
- **WHEN** a new contributor follows the README's install and run instructions exactly as written
- **THEN** every referenced path and command (e.g. `npm install`, `vercel dev`, `node --test tests/`, `vercel deploy --prod`) exists and works in the current repository

### Requirement: Canonical Agent Instructions
The repository root SHALL contain a single canonical agent-instructions file named `AGENTS.md` that accurately describes the current project layout and commands. The repository SHALL NOT ship per-tool instruction files (`CLAUDE.md`) or tool-specific configuration directories (`.claude/`) whose content is fully superseded or duplicated by other agent-tooling directories in the repository.

#### Scenario: Contributors find accurate agent instructions
- **WHEN** a contributor opens the repository root
- **THEN** an `AGENTS.md` exists that describes the actual Node.js/Vercel layout, commands, and security model.

#### Scenario: Legacy agent files are absent
- **WHEN** a maintainer checks for `CLAUDE.md` or the `.claude/` directory
- **THEN** neither exists in the tracked file list, and the openspec workflow is documented under `.opencode/` (and mirrored in `.agent/`).

### Requirement: Pull-request CI runs tests and lint
Every pull request targeting the `main` branch SHALL run the repository's unit test suite and its linter before the change can be merged, and a push to `main` SHALL run both as well.

#### Scenario: PR runs tests and lint
- **WHEN** a contributor opens or updates a pull request targeting `main`
- **THEN** the CI workflow runs `npm test` and `npm run lint` against the PR's head, and the PR is blocked if either fails

#### Scenario: push to main runs tests and lint
- **WHEN** a commit is pushed directly to `main`
- **THEN** the CI workflow runs `npm test` and `npm run lint` against the new head

### Requirement: README stays concise and defers internals
`README.md` SHALL be a concise, human-readable overview of the project (purpose, features, quick start, run/test/deploy commands, security summary) and SHALL link to `AGENTS.md` for architecture, per-file layout, and other churn-prone internals rather than duplicating them.

#### Scenario: README links to AGENTS.md for internals
- **WHEN** a reader opens `README.md`
- **THEN** the document links to `AGENTS.md` and does not contain a per-file code listing, per-file test descriptions, or provider/model environment-variable enumerations that are maintained in `AGENTS.md`

#### Scenario: README commands match the repository
- **WHEN** a new contributor follows the README's install and run instructions exactly as written
- **THEN** every referenced path and command (e.g. `npm install`, `npm run dev`, `npm test`, `npm run lint`, `vercel deploy --prod`) exists and works in the current repository
